# 图文与图片存储交接

本文对应 schema v5。源码与迁移可以共享；运营数据库、管理员账号、上传图片不提交到 GitHub。公开静态品牌照片在 `public/images/association/`，与本文的管理员运营上传是两个独立来源。

## 内容格式与迁移

- v5 在 `items` 追加 `body_format`，只接受 `plain` 或 `markdown`，旧记录默认 `plain`。已有正文不会被自动解释成 Markdown。
- 新建编辑器显式发送 `markdown`；旧 API 客户端不传格式时仍保存为 `plain`。
- 新增 `media_assets` 保存随机 ID、存储名、实际 MIME、大小、宽高、原名及创建时间，`item_media` 以外键关联文章与图片。
- 迁移每一版在事务中执行，失败回滚本版结构与版本号。上线前应先停写并备份数据库和图片目录，再在独立副本验证升级；此轮测试只使用内存数据库和临时目录，未迁移生产数据。
- Markdown 使用与阅读器一致的 GFM 语法树提取图片，包含表格、脚注中的图片，不把代码块中的示例链接当图片引用。绑定检查和文章保存同事务，缺失图片或关系失败会回滚正文与状态。
- 列表接口只返回摘要等列表字段，完整正文和格式从文章详情读取。

## 图片 API

`POST /api/admin/media?name=<原文件名URL编码>` 使用原始 File/Blob 二进制请求体，不是 multipart。必须使用管理员会话并同源；保留显式 Basic API 客户端无 Origin 的兼容。认证发生在读取正文之前。

允许的 `Content-Type` 为 `image/png`、`image/jpeg`、`image/webp`。单图最多 5 MiB、2000 万像素、任意边 8192 像素；拒绝动态图片。服务端检查签名并真实解码，应用图片方向、重新编码、剥离 EXIF 等元数据及尾随内容。SVG、HTML、任意附件、服务端远程抓图均不支持。

成功为 201：

```json
{"id":"32位随机十六进制ID","url":"/api/media/<id>","name":"原文件名","width":1200,"height":800,"size":123456,"mime":"image/jpeg"}
```

错误统一 `{ "error": "可显示的信息" }`：400 内容非法，401 未登录，403 来源非法，413 超限，429 单进程限流，500 存储失败。管理员未配置时沿用现有认证服务的 503。限流是单管理员、每进程每分钟 30 次尝试，不信任客户端转发 IP；多实例部署须另配共享配额或可信入口限流。

`GET /api/media/<id>` 的可见性随内容即时计算：

- 未绑定图片、草稿图：仅管理员可读；匿名返回 404。
- 至少一篇当前公开且格式为 Markdown 的文章引用：公众可读。公开状态沿用已发布、已收录、报名中、已归档。
- 撤回、从正文移除图片、改成纯文本或删除文章后，若没有其他公开引用，匿名读取立即返回 404。
- 不公开猜测图片是否存在；所有图片读取采用 `private, no-store`、`Vary: Cookie, Authorization`、`nosniff`。前端使用原生 `img`，或 Next Image 的 `unoptimized`，避免优化服务永久缓存私有图片。
- 文章 Markdown 图片地址只能是 `/api/media/<id>`，最多 50 张不同图片。HTML、外部图片、data URL 不可保存。普通链接只支持无内嵌凭据的 HTTP(S)。

## 文件目录与备份

新媒体目录为：

```text
AI_ASSOCIATION_DATA_DIR 已配置：<该绝对目录>/media/
未配置：<应用工作目录>/data/media/
```

新媒体遵循数据库相同的数据目录，不向旧目录回退。部署时应让该目录位于持久卷，应用用户可写；备份/恢复必须配对 `app.db` 与 `media/`。不要用 Git 同步运营资料。文件名由服务端随机生成，原名只作为元数据，不参与路径。

上传先解码再排他创建新文件；数据库插入失败时尝试清理本次新文件，不动旧文件。删除文章只删除关系，不自动删除可能共用的媒体文件。未保存文章的图片可保留为未绑定私有资产；当前不提供自动回收或全量删除任务，后续回收必须先核对引用与备份。

“清空业务数据”也只级联清除文章图片关系：媒体数据库记录和文件仍保留、转为仅管理员可读，不是磁盘擦除操作。不可把业务清空当作个人资料或上传文件的彻底删除。

**旧足迹附件兼容边界：** 现有 `src/lib/uploads.ts` 仍使用 `<应用工作目录>/data/uploads/`，不跟随 `AI_ASSOCIATION_DATA_DIR`，其已有 MIME/读取规则保持兼容。这轮不会自动迁移、复制或删除旧附件；备份已有足迹附件时需另备该目录。未来改造应单独制定数据迁移与回滚方案。
