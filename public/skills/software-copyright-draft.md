# 软著材料生成

## 什么时候用
- 项目已落地，要申请软著
- 手里有 README / 代码，但不知道怎么整理成材料

## 输入
1. 项目名 + 一句话介绍
2. 核心功能列表（3~5 条）
3. 技术栈
4. 源程序目录

## 步骤

### 1. 生成软件说明书
按这个结构写：
```
一、软件概述（背景、用途、运行环境）
二、主要功能（每个功能一段：做什么、怎么操作、结果）
三、技术特点（架构、关键技术）
四、运行环境（硬件、系统、依赖）
```

### 2. 检查源程序
- 前后各连续 30 页，共 60 页
- 每页不少于 50 行
- 页眉：软件全称 + 版本号
- 最后一页是程序结尾

### 3. 常见退回原因对照
- 页数不足 / 行数不够
- 页眉缺软件名或版本号
- 说明书里的功能和代码对不上
- 软件名称含"系统""平台"但材料体现不出来

## 输出
- 一份可直接提交的说明书初稿
- 一份源程序检查清单
