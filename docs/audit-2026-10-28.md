# 网站严格挑刺与改进报告（2026-10-28）

> 目标：网站用于**展示 AI 创客协会的成绩、活动与事迹**，并**收集成员做过的事、总结成员能力**。
> 本文按这个目标严格挑刺，给出解决方案与决策；已实施的改动同步在 PR #23。

## 一、调研参考

- [WCAG 2.1 AA 从零实践](https://ashishk9670.github.io/portfolio/blog/wcag-2-1-aa-from-scratch/)：焦点可见、语义标题层级、跳过导航、非文本内容替代，是作品/档案类站点的底线。
- [德州理工学生组织营销指南](https://www.depts.ttu.edu/rawlsbusiness/about/studentorgs/marketing/index.php)：学生组织对外展示应有清晰定位、成果与联系方式，内容要能快速浏览。
- 结合同类「协会/社团成果展示」站点的通行做法：成果墙（统一入口 + 筛选）、成员档案（可追溯）、团队成果合并展示、数据来源与更新时间标注。

## 二、严格挑刺清单（按目标对齐）

| # | 维度 | 问题（证据） | 严重度 | 解决方案 | 决策 |
|---|---|---|---|---|---|
| 1 | 定位 | 站点文案仍是「内部知识库」，与「展示协会成绩」目标不一致（`site.description`、导航） | 高 | 文案改为「AI 创客协会成果展示与成员能力档案」；导航加「成果墙」 | ✅ 已实施 |
| 2 | 展示入口 | 没有任何「成果/事迹」聚合页，访客只能翻内容库列表 | 高 | 新建 `/achievements` 成果墙：类型 / 部门 / 关键词筛选 + 统计条 | ✅ 已实施 |
| 3 | 数据重复 | 内容库回填按「每条内容 × 每位参与人」生成，成果墙同一成果出现 2~3 次（现场 29 条 → 19 个团队成果） | 高 | 按「标题 + 日期」合并为团队成果，列出全部参与人 | ✅ 已实施 |
| 4 | 能力总结 | 能力数据只在单页 AI 面板里，缺少全协会视角 | 高 | `/members` 增加「能力总览」：部门产出 / 成果类型 / 高频能力标签 / 贡献榜 | ✅ 已实施 |
| 5 | 可发现性 | 全站 `noindex`，与「对外展示」目标冲突 | 高（需决策） | 增加 `site.publicIndex` 开关（默认 false，因成员/项目仍是占位数据）；换成真实名单后改 true 即可全站收录 | ⚠️ 待站长确认后开启 |
| 6 | 数据可信 | 成员姓名、项目均为占位数据，但页面没有标注 | 高 | 页脚显示「示例数据 · 待替换为真实名单」徽标；`site.dataStatus` 一键切换 | ✅ 已实施 |
| 7 | 合规 | 投稿没有授权确认，可能收进他人隐私/未授权素材 | 高 | 表单增加必选「内容真实 + 公开授权 + 第三方素材已授权」勾选；服务端仍按三条红线审核 | ✅ 已实施 |
| 8 | 展示效果 | 成果只有文字，没有图片位 | 中 | 投稿新增「成果配图」URL 字段，贯通接口/成果墙/个人档案时间线 | ✅ 已实施 |
| 9 | 无障碍 | 无跳过导航；搜索框/反馈输入无 aria-label；标题层级跳级（h1→h4）；焦点样式依赖浏览器默认 | 中 | skip-link、`:focus-visible` 统一样式、补 aria-label、修正 h1→h2→h3 层级 | ✅ 已实施 |
| 10 | 隐私 | 成员档案含姓名/年级/部门，若未来开索引会外泄 | 中 | 档案页强制 noindex（即使全站开启收录）；搜索索引只放公开标题 | ✅ 已实施 |
| 11 | AI 汇总时效 | 档案 AI 文本需 agent 手动写回，没有自动触发 | 中 | 已有接口 `GET /submissions` + `PUT /profiles`；建议加定时任务/后台按钮（需要服务器配 LLM Key） | ⏳ 待站长配 Key |
| 12 | 数据维护 | 演示回填与真实投稿混在同一文件 | 中 | 记录带 `source: backfill/form` 字段，后台可区分；建议审核时优先处理 form | 🟡 已标注，后台可筛 |
| 13 | 部署 | 合并 ≠ 上线，服务器源码快照需 rsync 才能构建新版本 | 高 | 站长部署一次；长期建议配 SSH key 或 GitHub Actions 自动部署 | ⏳ 待站长 |
| 14 | 安全 | 后台默认口令仍在用（P0，上一轮已报） | 高 | 改服务器 `.env.admin` 并重启后台 | ⏳ 待站长 |
| 15 | 内容质量 | 4 篇攻略「使用记录」仍是 `[待补充]` | 低 | 内容运营事项：有实测数据后回填 | ⏳ 内容运营 |
| 16 | 性能 | 全站内联搜索索引 + 单页 52 个静态页；成果墙 19 条卡片可接受 | 低 | 投稿量过百后再考虑分页/虚拟列表 | 🟡 暂不做 |
| 17 | 真实素材 | 没有活动照片/现场图，展示力不足 | 中 | 已在投稿表单留配图字段；需真实活动素材，建议活动后整理上传 | ⏳ 需要素材 |
| 18 | 流程 | 无 CI，测试/构建靠本地手工 | 中 | 建议 GitHub Actions：`pnpm test && pnpm build && pnpm test:smoke` | ⏳ 待站长开权限 |

## 三、已实施（本次 PR）

- 新增 `/achievements` 成果墙：统计条、类型/部门/关键词筛选、团队成果合并、配图支持。
- `/members` 增加「能力总览」新区块（部门产出、成果类型、高频能力标签、贡献榜）。
- 全站定位文案、导航、页脚数据状态徽标更新；`site.publicIndex` 收录开关 + 档案页强制 noindex。
- 投稿表单：新增成果配图字段、必选授权勾选；接口保存 `image`；成果墙与档案时间线展示配图。
- 无障碍：skip-link、`:focus-visible`、搜索/反馈输入 aria-label、标题层级修正（首页 / 关于 / 资源 / 数据 / 详情）。
- 搜索索引加入「成果」条目（标题/成员/类型），成员链接改到个人档案页。
- 测试：投稿校验新增配图 URL 用例（44 项）；构建 52 页；烟雾检查通过。

## 四、推荐给站长的下一步（按优先级）

1. 改后台默认密码（`.env.admin` 的 `ADMIN_USERS`）+ 部署一次（rsync）——否则以上都只在 main/本地。
2. 换真实成员名单与真实项目数据（`src/data/members.ts`、`content/items.json`），换完把 `site.dataStatus` 改为 `real`。
3. 决定是否开放搜索引擎收录：真实名单换完后把 `site.publicIndex` 改 `true`（档案页仍 noindex）。
4. 配 LLM API Key（服务器 `.env.admin`）或在后台加「AI 汇总」按钮，让 AI 档案能自动刷新。
5. 配 GitHub Actions（推 main 自动测试/构建）与部署 SSH secret，减少手工步骤。
