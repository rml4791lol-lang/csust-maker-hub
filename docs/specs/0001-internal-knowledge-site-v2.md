# Spec：内部知识站 v2 — 五类内容 + agent 生产 + 最小后台

## Problem Statement

技术部现在的情况：

- 做过的东西散在群文件、飞书文档、个人电脑里，找一次要问一圈人。
- 有值的经验只留在当事人脑子里，人一换届就断。
- 内容靠人手写，写一篇要一两个小时，产不出来。
- 想放开让别人也发，但没有审核和后台，不敢。
- 线下培训办完就散了，录音、资料、复盘留不下来，下一届从零开始。

结果：网站做出来了，但没东西可看，也没人愿意往上放。

## Solution

把它做成**内部用的攻略库**，不是官网：

1. 内容只要五类，每类有固定结构，agent 能直接写、能直接读。
2. 生产流程固定：录音 → agent 整理成初稿 → 人工确认 → 发布。
3. 一个最小后台：2 个管理员 + 1 个 agent 账号，能看列表、点发布、一键下架。
4. 每篇文章底部有「有用 / 没用」反馈，汇总到飞书。
5. 线下培训和培训档案分开：通知有时效，档案长期留。
6. 不对外、不被搜索引擎收录。

## User Stories

1. 作为内部成员，我想在首页直接看到最近收录了什么，这样不用问别人“最近有没有新东西”。
2. 作为内部成员，我想按分类浏览（攻略 / 技能指令 / 模板素材 / 外部项目 / 培训），这样知道从哪找。
3. 作为内部成员，我想打开一篇攻略就看到「问题场景 → 现成路径 → 可复制提示词 → 我们自己的使用记录」，这样能直接照做。
4. 作为内部成员，我想一键复制技能指令，这样能直接粘给 agent 用。
5. 作为内部成员，我想下载模板文件，这样不用自己从零做。
6. 作为内部成员，我想点开外部项目链接直接跳到 GitHub 原文，这样不被二次转述误导。
7. 作为内部成员，我想看到线下培训的通知和报名入口，这样不会错过。
8. 作为内部成员，我想在培训结束后找到资料、录音和复盘，这样没去也能补。
9. 作为内部成员，我想在每篇内容底部点「有用 / 没用」并留一句话，这样我知道我遇到的问题有没有被回应。
10. 作为内部成员，我想看到内容是谁写的、谁审的、什么时候更新的，这样能判断内容是否可信。
11. 作为内部成员，我想在手机上也能正常看，这样群里转过来能直接打开。
12. 作为内容整理人（agent），我想按固定格式写入文件，这样不会因为格式不对导致页面坏掉。
13. 作为内容整理人（agent），我想在写入时标记为草稿，这样不会误发布。
14. 作为审核人，我想在后台看到待确认的列表和内容预览，这样能快速判断。
15. 作为审核人，我想一键发布或退回，这样不用碰代码。
16. 作为审核人，我想一键下架已发布内容，这样出问题能立刻止损。
17. 作为审核人，我想看到每条内容的审核记录（谁审的、什么时候、agent 还是人），这样出了问题能追溯。
18. 作为审核人，我想在发布前逐条对照合规红线（政治敏感 / 隐私 / 未授权转载），这样不踩法律风险。
19. 作为管理员，我想用账号密码登录后台，这样不用接第三方登录。
20. 作为管理员，我想在后台看到反馈汇总（哪篇有用、哪篇收到投诉），这样知道该改什么。
21. 作为管理员，我想限制只有内部能访问，这样内容不外流。
22. 作为团队，我想在内容出错时（字段缺失、引用断链）在构建阶段就报错，而不是上线后才发现。
23. 作为团队，我想每次发布都有记录，这样换届交接时能看到历史。

## Implementation Decisions

### 内容模型

- 内容以 Markdown + frontmatter 存放，agent 直接读写，人也能读。
- 五类内容：攻略（guide）、技能指令（skill）、模板素材（template）、外部项目（link）、培训（training）。
- 每类有固定必填字段，缺字段在校验阶段报错。
- 攻略结构固定四段：问题场景、现成路径、可复制提示词、我们自己的使用记录。
- 技能指令：指令正文（等宽）+ 适用 agent（Claude Code / Codex / Cursor）+ 一句话效果。
- 外部项目：标题 + 一句话价值 + 链接，**不做详情页**。
- 培训：通知类（有时间、报名链接）与档案类（资料、录音、复盘）分开存放。

### 内容状态机

```
draft（agent 写入）→ reviewing（待人工确认）→ published（发布）
                                      ↘ rejected（退回，附原因）
published → unpublished（下架，留痕）
```

状态流转必须记录操作人、时间、方式（agent / 人工）。

### 后台

- 使用现成 Git-based CMS（Sveltia CMS 或 Decap CMS），挂在 `/admin`，不自己从前端写后台。
- 认证：账号密码，2 个管理员 + 1 个 agent 服务账号。不做注册、不做找回密码。
- 后台只做四件事：列表、预览、发布/退回、下架。
- 内容编辑仍由 agent 改文件完成，后台不承担编辑器职责。

### 审核

- agent 先做初审（事实、格式、合规红线），输出结论。
- 人工做终审，点发布。
- 每条内容记录：审核人、审核时间、审核方式（agent / 人 / 双审）。

### 反馈

- 每篇内容底部两个按钮（有用 / 没用）+ 一行可选说明。
- 数据汇总到飞书多维表格，不与站点后端耦合。

### 访问边界

- 全站 `noindex`，不被搜索引擎收录。
- 一期不加密码；涉及成绩、手机号等内容时再上访问控制。

### 部署

- 保持现有静态构建 + 同步到服务器的方式，不引入新的部署链路。

## Testing Decisions

好的测试只验证外部行为：给定内容文件，站点是否按预期产出；不测组件内部实现细节。

### 接缝 1：内容数据校验（主接缝）

- 位置：数据层，纯函数，不启动浏览器。
- 覆盖：必填字段齐全、字段类型合法、id 唯一、成员↔项目等引用不断链、状态值在允许集合内。
- 理由：内容由 agent 批量生成，最高频的错误就是字段缺失和引用断链；这个接缝最快、最便宜。

### 接缝 2：构建烟雾检查

- 位置：构建产物（HTML）。
- 覆盖：构建成功；五类内容列表页和详情页存在；首页包含最新条目标题；详情页包含正文与审核信息。
- 理由：静态站的最终交付物是 HTML，构建错了整站就是空的。

### 暂不设

- 后台 API 契约测试：后台落地的同一个改动里补，不提前造空壳。
- 视觉回归、链接有效性检查：一期不做。

### 测试工具

- 引入 Vitest 作为唯一测试运行器；构建烟雾检查用 Node 脚本断言 `dist/` 产物。
- 现有代码没有测试先例，这两个接缝即建立基线。

## Out of Scope

- 站内搜索（一期内容少，不需要）
- 视频托管与播放
- Token 额度网关（见 ADR-0001，已决定暂缓）
- 公开访问与对外官网
- 用户注册、找回密码、角色分级
- 评论、点赞、收藏
- 内容编辑器（编辑由 agent 完成）
- 视觉回归、链接有效性检查

## Further Notes

- 合规红线三条：不涉政治宗教民族敏感；不发他人隐私与未公开数据；不转载未授权付费内容与破解教程。审核时逐条对照。
- 生产流程是「录音 → agent 转写整理 → 人工确认」，本 spec 假设这条链路成立。
- `ai.an520.xin` 是个人 IP 站，与本项目并存、不合并；本项目形态可参考它，但内容面向协会内部场景。
- 成功标准（上线一个月）：① 3 个非技术成员主动打开过；② 1 人照着内容做出东西；③ 有人问下一篇什么时候。
