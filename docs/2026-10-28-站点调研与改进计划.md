# 站点调研与改进计划（2026-10-28）

> 调研方式：构建产物分析 + 多断点浏览器审计（1440 / 768 / 430）+ 全站链接检查 + 后台 API 功能/安全实测 + 数据与代码静态检查。
> 结论：**功能链路可用、样式统一，但上线与性能/可读性方面还有硬伤**。下面按优先级给出问题与修复计划。

## 二、问题清单（按优先级）

### P0：上线阻断 / 安全

1. **线上还是旧站**：`an520.xin` 打开是旧版标题与内容，新功能（账号、上传、审核、管理端、新设计）都没上线。
2. **公开仓库暴露部署信息**：GitHub 仓库是 PUBLIC，README 含服务器 IP、用户名、部署路径、后台路由与默认 Basic 账号提示（`admin:admin123`）。若线上后台仍是默认密码，属于高危。
3. **没有备份机制**：账号（`DATA_DIR/accounts.json`）、会话密钥、审核日志只存在服务器本地；没有备份脚本/恢复流程文档，服务器故障即全丢。
4. **审核后不自动发布**：`/manage` 通过账号、审核照片、同步成员后，前台要人工去 `/admin` 点「重新构建」，漏点就会出现「后台已通过、前台看不到」。

### P1：体验与质量

5. **小字号回潮**：`app-theme.css` 有 23 处、`global.css` 有 148 处 <14px 声明；实测首页每页 8 处 11–13px。违反此前「任何页面不小于 14px（五号）」的规范。
6. **性能超标**：
   - CSS 单文件 324KB，覆盖率仅 ~6%（大量旧版样式/208 条 @font-face 未使用）；
   - 字体：首页 1.1MB、成果页 1.9MB（Noto Sans/Serif SC 的 CJK 分片全量引入）；
   - 首页 three.js chunk 729KB；首页总 2.2MB，成果页 3.1MB；
   - 现场照片单张 150–216KB，未做 WebP/响应式；未用的旧装饰图 4 张 + 旧照片 5 张（约 1.4MB）仍随构建发布。
7. **可访问性**：
   - `/contribute` 上传文件输入没有 label；
   - `/register` 身份/部门单选按钮没有 `fieldset/legend` 分组语义；
   - 部分 12px 灰色小字（成员 meta、AI 建议、部门行）对比度与字号都偏低；
   - 图片链接缺显式 `aria-label`（虽 img alt 可提供可访问名，但建议补）。
8. **安全加固**：
   - 后端无 `Content-Security-Policy`、`X-Frame-Options`、`X-Content-Type-Options`、`Referrer-Policy`、`HSTS`；
   - `clientIp()` 直接信任 `X-Forwarded-For` 第一个值，攻击者可伪造头绕过登录/投稿限流（Caddy 需显式 trust 并取可信值）；
   - 会话是 7 天无状态 HMAC，改密码后旧会话仍有效，没有「退出所有设备」；
   - 上传只校验文件头，不剥离 EXIF（可能泄露拍摄位置）；前端压缩可剥离，但 API 直传绕不过去；
   - 登录限流只按 IP（12 次/10 分钟），没有按账号锁定。
9. **工程保障缺失**：没有 CI（GitHub Actions），后端接口没有自动化测试（目前只靠手工脚本验证）；`admin-server.ts` 单文件 1700+ 行，继续加功能会难维护。

### P2：内容与长期优化

10. **演示数据**：成员/投稿/相册仍是示例；成员档案页展示的是演示人物。真实数据上线前不能对外宣传。
11. **首页小问题**：`5 RECENT WORKS` 的 5 是显示条数（slice 截断）而非总数，语义不准；英文标语可再校对。
12. **死代码/冗余**：旧 `global.css` 3.5k 行 + 旧首页/底部/装饰样式已无引用；旧装饰图与旧照片未清理。
13. **内容运营**：管理端缺筛选/批量操作/导出（成员 CSV）；审核记录只记日志，没有可视统计；无监控/错误上报。
14. **SEO/分享**：全站 noindex 是有意为之；但目前没有 `robots.txt`、`sitemap`，等真实数据上线时可补。
15. **依赖**：`tailwindcss` 插件在 `astro.config.mjs` 里挂着，但项目实际未用 Tailwind；可移除减构建复杂度。

## 三、修复计划（建议顺序）

### 阶段 A：先能安全上线（P0，约 1 天）

1. 部署新站 + 后台：服务器 `git`/`rsync` 部署、Caddy 反代 `/admin`、`systemctl restart` 后台、`SUPER_ADMIN_*` 环境变量、`DEPLOY_TARGET` 配好。
2. 立即轮换安全信息：换掉默认 Basic 账号、`SUPER_ADMIN_PASSWORD`、`AGENT_TOKEN`；README 删除服务器 IP/账号细节（移到私有文档）。
3. 备份：写 `scripts/backup.sh`（打包 `DATA_DIR` + `content/` + `.env.admin`），加 crontab 每日备份；写恢复步骤。
4. `/manage` 加「发布到线上」按钮（调用已有 `POST /api/build`，带确认与进度提示）；审核/照片通过/成员同步后提示「需要发布」并给一键入口。
5. 上线验收清单：注册→审核→登录→投稿→上传→照片审核→管理端授权→重新构建→前台核对。

### 阶段 B：可读性 + 性能 + 可访问性（P1，约 2–3 天）

6. **字号统一**：把 `app-theme.css`/`global.css` 里所有 <14px 声明提到 14px（小标签 14、正文 16、标题按现有 clamp），跑审计脚本确认全站 0 处 <14px。
7. **CSS 瘦身**：删除旧 `global.css` 中已无引用的样式（tnav/tfoot/hero 旧版/decor 等），目标 CSS <60KB；同时移除未用 Tailwind 插件。
8. **字体方案**：CJK 改用系统字体栈（PingFang SC / Microsoft YaHei / Noto Sans SC system），仅对拉丁/数字使用本地 JetBrains Mono（或 Inter），字体体积目标 <200KB；删除 Noto CJK 全量分片。
9. **图片优化**：现有照片生成 WebP（`<picture>` + srcset，移动端小图），清理未用装饰图/旧照片；`three.js` 首屏延后加载（先静态线框，空闲再加载 3D）或降级为轻量 canvas 线框。
10. **可访问性修复**：上传输入加 label/aria；身份/部门加 `fieldset+legend`；小字提亮；图片链接补 aria-label。
11. **安全头**：Caddy 增加 CSP（允许 inline script/样式按现状）、XFO、XCTO、Referrer-Policy、HSTS；后端对敏感响应也补 XCTO。
12. **后端加固**：可信代理 IP 解析（Caddy 设置 `trusted_proxies` 或改用 Caddy 提供的真实 IP 头）、改密码后作废旧会话（账号加 `sessionVersion`）、上传剥离 EXIF（可用 sharp，Astro 已带）、登录按账号加锁定。
13. **CI**：GitHub Actions 跑 `pnpm test` + `pnpm build` + `smoke`；后端接口加集成测试（起 3210 测注册/审核/投稿/上传/越权）。

### 阶段 C：内容与运营（P2，真实数据到位后）

14. 真实成员注册→管理端审核→同步成员档案→重建，替换全部演示数据；准备 4 场活动的高清照片与成果材料。
15. 管理端增强：成员导出 CSV、审核筛选、按时间/状态统计；首页英文校对；补 robots/sitemap（开放收录时）。
16. 代码整理：拆分 `admin-server.ts`（auth / content / uploads / manage 模块），清理历史 `items.json` 引用。

## 四、验收指标

- 上线：`an520.xin` 为新版；后台 `/manage` 可登录；发布按钮可用；备份任务存在。
- 性能：首页总请求 <600KB、成果页 <1MB；CSS <60KB；字体 <200KB；LCP < 2s（本机）。
- 可读性：全站 0 处 <14px；移动端无横向溢出。
- 可访问性：所有表单控件有 label；键盘可完成主要流程。
- 安全：5 项安全头齐全；伪造 XFF 不能绕过限流；改密码后旧会话失效；上传图片无 EXIF。
- 工程：CI 绿；后端关键接口有自动化测试。
