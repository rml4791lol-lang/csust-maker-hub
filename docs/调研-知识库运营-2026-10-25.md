# 调研：知识库运营 — 为什么大多数内部知识站会死，我们怎么活下来

日期：2026-10-25。基于第一性原理 + 业界实践共识，给出带技术路径的优先级 backlog。

## 一、第一性原理：这个站到底是什么

把「做过的东西」变成「下一个人能直接拿走用的东西」。拆到底只有三个物理事实：

1. 知识在个人脑子里，换届就蒸发 → 所以要有站。
2. 写一条内容的时间成本 >> 读一条 → 所以生产必须便宜（agent 骨架、录音转写），质量靠标准（g01 五段）兜底。
3. 没人看、没反馈的内容等于不存在 → 所以分发和反馈不是附加功能，是生存条件。

Spec 的成功标准就是这三条的度量：① 3 个非技术成员主动打开过（分发）；② 1 人照着做出东西（可用性）；③ 有人催更（需求拉力）。

**核心闭环：生产 → 审核 → 分发 → 使用 → 反馈 → 更新。** 任何一环断了，整条链退化成「文件柜」——这正是大多数知识库的死法。

## 二、业界共识：知识库的死因（调研结论）

综合 2025 年实践文章的共识，失败极少是技术问题，几乎全是运营问题：

| 死因 | 表现 | 对照我们的现状 |
|---|---|---|
| 无维护机制 | 内容老化，读者失去信任，没人再打开 | ⚠️ 无复核机制；tr01 这类时效内容靠手动 |
| 无 owner | 文档成孤儿，换届断档 | ⚠️ 有 author 字段但无复核周期 |
| 找不到 | 站一大就没人能快速找到对的东西 | ✅ 十类筛选 + ⌘K 搜索 + 新手入口 |
| 无分发 | 「发了没人知道」，靠用户自己想起来刷 | ❌ **最弱一环：发布后没有任何主动触达** |
| 主动使用被忽视 | 部署成被动文件柜，没人知道谁在用、有没有用 | ✅ 已有浏览量 + 有用/没用落库与后台汇总 |

## 三、本次已闭环的（2026-10-25）

- **使用与反馈回路**：浏览打点、有用/没用落库、后台反馈汇总面板、数据页实时排行——「没人知道谁在用」已解决。
- **生产成本**：`GET /admin/api/scaffold?type=…` 按类型吐内容骨架（含 g01 标准提示），agent 写稿不再从零想结构。
- **新鲜度机制**：每日 03:30 定时构建 + expiresAt 过期自动下架；tr01 已补上真实过期时间。
- **后台实时性**：后台页面改读实时内容（原来 agent 改完要重启才可见）。

## 四、Backlog（按对成功标准的贡献排序）

### P0：飞书群机器人推送（分发——当前最弱一环）

发布即推送卡片到群里（标题 / 作者 / 一句话 / 链接），让「发了」等于「被看到」。直接服务成功标准 ①③。

技术路径（调研确认的标准做法）：
1. 飞书群里加自定义机器人（custom bot），拿 webhook URL + 签名 secret —— 需要你提供，放服务器 `.env.admin`（`FEISHU_WEBHOOK` / `FEISHU_SECRET`）。
2. `admin-server.ts` 的 `setState()` 是现成钩子点：`to === 'published'` 时 POST 消息卡片（HMAC-SHA256 签名，注意频控与合并）。
3. 无飞书可用微信群的替代：企业微信群机器人 webhook（无需签名，更简单）。

### P0：内容 Owner + 复核周期（保鲜）

- 每条内容必须有 `author`（校验从可选变必填，validate 加 warn）。
- `reviewedAt` 超过 90 天的内容在后台标「待复核」，复核按钮刷新 `reviewedAt`。
- 时效类内容（training/notice）强制 `expiresAt`（tr01 漏设就是例证，已补）。

### P1：双周内容值班（人治补机器）

每期一人负责收 1 条新内容（轮换表挂在 about 页或后台）。内容站的产线问题本质是排班问题。

### P1：反馈周报

每日构建后把「新增反馈 + 浏览 Top3 + 即将到期」推给管理员（复用飞书机器人，P0 完成后顺路）。

### P2：「照做成功」结构化

反馈按钮加第三态「我照做出来了」→ `usage.confirmations` 计数。这是成功标准 ② 的直接度量，比「有用」强得多。

### P3：飞书多维表格同步（spec 原设想）

内容和反馈沉淀到多维表格，方便非技术成员浏览和统计。等 P0/P1 跑顺再做，避免过早集成。

## 五、不做的事（第一性原理推导出的克制）

- 不做站内全文检索升级、不做评论收藏——内容 < 50 条时全是伪需求，浏览 + 筛选够用。
- 不做积分激励系统——把「值班」排进现有分工比造一套游戏化便宜且真实。
- 不做对外公开——内部信任密度高的时候，开放反而提高写作者的顾虑。
