# ADR-0001：Token 额度网关（New API）暂缓

- 日期：2026-10-25
- 状态：已决定（暂缓，非否决）

## 背景

设想：给成员、之后给全校学生发放免费 AI 额度（例如每人每天 1 亿 token），需要一个额度管理网关 + 可视化后台。

## 调研结论（已验证）

1. **中科大的「词元计划」网关源码不可用。** `git.ustc.edu.cn` 校外访问返回 401，必须申请账号；且公开信息显示其仓库更像「成长营」课程与项目合集，不是可直接部署的产品。
2. **New API 的「每日/每月额度」尚未进正式版。** 相关 PR（[#3345](https://github.com/QuantumNous/new-api/pull/3345)、[#5791](https://github.com/QuantumNous/new-api/pull/5791)）均为 OPEN 状态；最新版 v1.0.0-rc.46 无此能力。要实现「每天自动重置额度」需自建定时脚本。
3. **New API 原生可用的能力**：用户管理、总额度、兑换码批量生成、日志统计、分组、令牌级 RPM/TPM 限流。这些足够做「发放 + 限额」，不够做「按时间窗口分层限额」。
4. **成本无法确认。** 服务器上无历史用量数据，实际成本取决于真实使用率与缓存命中率，不能按额度上限估算。
5. **可替代参考**：[OpenKeyHub](https://github.com/buBailai/OpenKeyHub)（学校场景开源多租户网关）、[解字计划](https://github.com/jiezi-ai)（大学生 token 资助项目）。

## 决定

**暂缓。** 当前阶段不部署额度网关，不投入开发。

## 理由

- 核心诉求是「网站能正常收录信息和视频」，额度发放不是当前最紧的一环。
- 额度网关联动身份认证、成本与风控，属于跨学期工程，不应阻塞内容建设。
- 没有真实用量数据时定额度，等于拍脑袋。

## 重新评估的条件（任一满足）

1. 有明确经费来源，且知道大致可用额度。
2. 需要服务的人数超过当前人工发放可承受的范围。
3. New API 的周期额度 PR 合并进正式版，部署成本显著下降。
4. 内容站已有稳定使用量，适合接额度作为留存手段。

## 若重开，推荐路径

1. 服务器上独立端口部署 New API 测试实例（不改动现有站点）。
2. 生成 5 个兑换码，3~5 人试用一周，记录真实消耗与成本。
3. 用定时脚本实现「每天重置额度」，不做复杂的窗口限流。
4. 有数据后再谈推广范围。
